# /build: как реализуем тикет

Если указан id тикета, возьми его из `docs/tickets.md`. Иначе возьми первый `todo` без незавершённых зависимостей.

## Перед началом
Прочитай `CLAUDE.md`, критерии приёмки тикета в `docs/spec.md`, `docs/brand.md`, `docs/facts.json` и нужный `docs/copy-*.md`. Если токены бренда не заполнены, остановись и запиши вопрос.

## Правила кода
1. Только HTML, CSS, JavaScript. Без npm-пакетов, сборки, CDN, внешних шрифтов и ES-модулей.
2. Логику пиши в `*-logic.js` как чистые функции без обращения к DOM. Внизу файла:
```js
(function (root, factory) {
  if (typeof module !== 'undefined' && module.exports) module.exports = factory();
  else { root.GL = Object.assign(root.GL || {}, factory()); }
})(typeof self !== 'undefined' ? self : this, function () {
  // ...функции...
  return { /* экспорт */ };
});
```
3. Интерфейс (`demo-*.js`, `lead-form.js`) только подключает логику к DOM и использует `window.GL`.
4. Цвета, шрифты, скругления только через CSS-переменные из `base.css`, значения из `docs/brand.md`.
5. Тексты на странице из `docs/copy-*.md`. Новые тексты только для мелких подписей интерфейса.
6. Числа с %, «млн», «тыс.», ₽ в статичном тексте только из `docs/facts.json`. В демо числа допустимы: их вымышленность раскрывает сноска в футере.
7. Каждое демо: контейнер с `data-demo="d1"` и т. д., кнопка «Сбросить демо». Пометок «Демо-данные» и «Тестовая работа» на странице нет, только сноска в футере.
8. Каждая страница: `lang="ru"`, viewport, `title`, `meta description`, один `h1`, сноска «Тестовое задание» в подвале.
9. Доступность: `label` у полей, видимый `:focus-visible`, управление с клавиатуры, `aria-live` для результата формы и изменяющихся чисел, `alt` у картинок.
10. Видео: `autoplay muted loop playsinline`, `poster`, под `prefers-reduced-motion` показывать постер.

## Порядок
1. Реализуй самую маленькую рабочую версию тикета.
2. Запусти `node scripts/check.mjs` и `node --test`, исправь свои ошибки.
3. Для UI открой страницу локально (`python3 -m http.server 8000` в папке `site`, адрес `http://localhost:8000`) и проверь руками главные сценарии, если у тебя есть браузерный инструмент. Если нет, честно напиши в отчёте, что визуально не проверено.
4. Отчёт: что сделано, какие файлы, результат проверок, что неясно.
