# /review: как ревьюить

Читай как скептик. Цель: найти то, что разработчик не заметил.

## 1. Запусти проверки
`node scripts/check.mjs --strict` (для полного ревью) или `node scripts/check.mjs` (для тикета) и `node --test`. Результат укажи в вердикте.

## 2. Критерии приёмки
Пройди по `AC-xx`, относящимся к тикету. Для каждого найди доказательство в коде: файл и строка. Нет доказательства означает блокер.

## 3. Контент
- Все тексты соответствуют `docs/copy-*.md`.
- Нет выдуманных отзывов, клиентов, кейсов, логотипов и чужих брендов.
- Числа с %, «млн», «тыс.», ₽ в статичном тексте есть в `docs/facts.json`.
- Нет обещаний результата («вырастете», «гарантируем»).
- Сноска в футере раскрывает тестовое задание и вымышленные демо-данные; других пометок «демо» и «тестовая работа» на странице нет; калькулятор содержит оговорку про допущения.

## 4. Код
- Нет внешних ресурсов и зависимостей, скрипты классические.
- Логика отделена от DOM, UMD-экспорт присутствует.
- Нет дублирования больших кусков между страницами A и B, общее вынесено в `assets/`.
- Нет `console.log` и мёртвого кода.
- Ошибки обработаны: пустые данные, отсутствие свободных курьеров, ошибка отправки.

## 5. Доступность и адаптив (по коду)
- `label` у каждого поля, `aria-invalid` и `aria-describedby` при ошибках, `role="status"`/`role="alert"` у результатов формы.
- Все интерактивные элементы доступны с клавиатуры, есть `:focus-visible`.
- Контраст по токенам `brand.md` не ниже 4.5:1 (посчитай по формуле WCAG для основных пар цветов).
- Есть правила для ширины 360 px, нет фиксированных ширин больше экрана.

## 6. Бренд
Токены используются через переменные, а не жёстко прописаны. Тёмная тема, светлая кнопка CTA, пиксельный стиль только в иллюстрациях.

## 7. Что нельзя проверить без человека
Перечисли в вердикте: внешний вид, уместность видео, ощущение на телефоне.

Вердикт пиши строго в формате из `.claude/agents/reviewer.md`.
