# Проект: два лендинга для Goulash.tech (тестовое задание)

Владелец проекта: Ася. Язык общения и текстов сайта: русский. Объясняй простыми словами, без жаргона, команды терминала давай готовыми к копированию.

## Что это
Статический сайт из трёх страниц в папке `site/` (выбор, лендинг A «гост-китчены», лендинг B «своя доставка»). Подробности в `docs/spec.md`. Это единственный источник требований.

## Главные правила
1. `docs/spec.md`, `docs/copy-*.md`, `docs/facts.json`, `docs/brand.md` меняет только человек. Если там неясно, запиши вопрос в `docs/questions.md`, прими самое разумное допущение, отметь его и иди дальше.
2. Тексты на странице берутся из `docs/copy-*.md`. Новые тексты только для мелких подписей интерфейса (кнопки, подсказки, ошибки).
3. Числа с %, «млн», «тыс.», ₽ в статичном тексте только из `docs/facts.json`. Никаких выдуманных отзывов, клиентов, кейсов и логотипов клиентов.
4. Всё выдуманное в демо раскрывается одной сноской в футере каждой страницы: «Тестовое задание. Это не официальный сайт Goulash.tech, демо-данные вымышлены». Других пометок «демо» и «тестовая работа» на странице нет (решение Аси 2026-11-16).
5. Только статика: HTML, CSS, JavaScript. Без фреймворков, сборки, npm-пакетов, CDN и внешних шрифтов. Скрипты классические, не ES-модули.
6. Логика в чистых функциях файлов `*-logic.js` в формате UMD (см. ТЗ, раздел 3), интерфейс отдельно. Контракты функций в ТЗ нельзя менять.
7. Не собирай настоящие персональные данные. Форма только имитирует отправку.
8. Цвета, шрифты и скругления только из токенов `docs/brand.md`, оформляй их CSS-переменными в `site/assets/css/base.css`.
9. Всё сгенерированное (картинки, видео, тексты) записывай в `docs/prompts.md`.

## Как работать
- Проверки: `node scripts/check.mjs` (мягко) или `node scripts/check.mjs --strict` (всё), `node --test`.
- Прежде чем сказать «готово», запусти обе проверки сам и покажи результат. Не доверяй отчётам других агентов, проверяй сам.
- Один тикет за раз, маленькими шагами. После каждого тикета короткая запись в `docs/log.md`: id, что сделано, что проверено.
- Ревью делает отдельный агент `reviewer` в чистом контексте. Он не правит код, только пишет замечания.
- Максимум 2 круга «ревью, правка» на тикет, дальше статус `blocked` и запись в `docs/questions.md`.

## Команды (скиллы)
`/brand-extract`, `/grill-me`, `/to-spec`, `/to-tickets`, `/pipeline`, `/build`, `/review`, `/verify`, `/media`, `/ship`, `/retro`. Описание каждой в `.claude/skills/<имя>/SKILL.md`.

## Контрольные точки человека
`docs/checkpoints.md`. Без отметки C1 не начинать разработку, без C2 не делать лендинг B. Не отмечай их сам.
