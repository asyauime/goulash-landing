# Goulash.tech: лендинг для двух ролей (тестовое задание)

**Сайт:** https://asyauime.github.io/goulash-landing/

Тестовое задание на позицию AI-дизайнера: лендинг продукта «Гуляш» (Goulash.tech) для двух аудиторий, с рабочей формой заявки, интерактивными демо интерфейса и сгенерированным видео. Это не официальный сайт Goulash.tech, демо-данные вымышлены.

Главное в работе не только сайт, но и **управляемый процесс с ИИ**: ТЗ с проверяемыми критериями, тикеты, агент-разработчик, независимый агент-ревьюер, автопроверки и тесты, пробники перед внедрением, журнал всех генераций.

## Что на сайте

Одна страница, две роли (`site/kitchens/index.html`, корень сайта переводит на неё):

- **Гост-китчены и виртуальные бренды** (основная роль): первый экран с заставкой, где LED-точки собираются в значок кухни, три боли с переключателем «Без / С Goulash.tech», видео, «Кому подходит», «Как это работает» (шаги едут по маршруту с пиксельным курьером), «Что входит» с живыми мини-интерфейсами, демо, факты, подключение, вопросы, форма.
- **Рестораны, кофейни и пекарни со своей доставкой**: блок «Своя доставка» со своими болями, калькулятором комиссий агрегаторов и приложением гостя.
- **Пять интерактивных демо** на вымышленных данных: доска заказов, стоп-лист и меню гостя, маршрут и время доставки, калькулятор комиссий, приложение гостя.
- **Форма заявки**: валидация, маска телефона, загрузка, успех и ошибка (ошибку можно вызвать адресом с `?simulate=error#form`).
- **Видео** (27,5 с, со звуком и подписями) раскрывается по прокрутке, кнопки «Пауза» и «Включить звук».
- Плавные полутоновые переходы из точек между тёмными и светлыми секциями, страница 404, фавикон и обложка для превью ссылки.
- Доступность: клавиатура, `prefers-reduced-motion` (всё движение выключается), подписи у полей и кнопок, работает без JavaScript в упрощённом виде.

Только статика: HTML, CSS и классический JavaScript, без фреймворков, сборки и внешних ресурсов. Вес около 4,8 МБ.

## Как устроен процесс

```
бриф → аудитории и гипотезы → ТЗ с критериями приёмки и тексты → тикеты
  → разработчик (агент builder) → автопроверки и тесты → ревьюер (агент reviewer, чистый контекст, код не правит)
  → не больше 2 кругов «ревью → правка», иначе blocked и вопрос человеку
  → пробник для спорного дизайна → выбор человека → внедрение → выкладка
```

- **Человек решает, агенты делают.** Ася утверждает ТЗ и тексты, смотрит результат, выбирает варианты в пробниках, решает спорные вопросы. Агенты не меняют ТЗ сами: неясности и допущения пишут в `docs/questions.md`.
- **Проверяемые критерии.** В `docs/spec.md` 30 критериев приёмки (AC-01…AC-30), у каждого способ проверки: автоматически, тестом, ревьюером или глазами.
- **Автопроверки перед каждой выкладкой:** `node scripts/check.mjs --strict` (язык, заголовки, внешние зависимости, битые ссылки, выдуманные числа, форма, демо, видео, вес) и `node --test` (27 тестов логики формы и демо).
- **Независимое ревью** после каждой задачи: отдельный агент в чистом контексте, вердикт PASS/FAIL и замечания «блокер / не блокер».
- **Пробники перед внедрением:** анимации, видео и его качество сначала показываются в `docs/drafts/*.html`, на сайт идёт только выбранное.
- **Журналы:** `docs/log.md` (что сделано и проверено по каждой задаче), `docs/prompts.md` (все генерации и инструменты), `docs/questions.md` (вопросы и решения).

## Как посмотреть локально

В терминале из папки проекта:

```
python3 -m http.server 8000 --directory site
```

Затем откройте `http://localhost:8000/kitchens/`. Остановить сервер: Ctrl+C.

Проверки:

```
node scripts/check.mjs --strict
node --test
```

## Команды процесса (Claude Code)

`/grill-me` (интервью по задаче), `/to-spec` (ТЗ), `/to-tickets` (тикеты), `/pipeline` (разработка, ревью, проверки по тикетам), `/build`, `/review`, `/verify` (итоговый отчёт), `/media` (бриф и журнал генераций), `/ship` (выкладка), `/retro` (ретроспектива). Описание каждой в `.claude/skills/<имя>/SKILL.md`.

## Честные ограничения

- Автопроверки ловят то, что проверяется текстом и логикой. Узнаваемость бренда, уместность видео и удобство на телефоне проверяет человек (`docs/checklist.md`).
- Агенты проверяли сайт в Chrome на компьютере и в эмуляции телефона. Звук и поведение iOS Safari проверяются только на настоящем телефоне.
- `check.mjs` читает HTML регулярными выражениями: нестандартная разметка может дать ложное срабатывание.
