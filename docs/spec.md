# ТЗ: лендинг Goulash.tech для двух ролей (тестовое задание)

Версия 2.0 (2026-11-17). Владелец ТЗ: Ася (человек). Агенты ТЗ не меняют: если что-то неясно или противоречиво, они пишут вопрос в `docs/questions.md` и продолжают с самым разумным допущением, помечая его.

Что изменилось в 2.0 (решение Аси 2026-11-17, журнал F18): вместо трёх страниц (выбор, лендинг A, лендинг B) одна страница. Основная роль, гост-китчены, задаёт всю страницу; вторая роль, рестораны с собственной доставкой, получает свой блок «Своя доставка» с двумя демо. Лендинг B и страница выбора не делаются. Видео с сайта убрано (решение Аси 2026-11-17, F22).

## 1. Цель

Сдать ссылку на работающий лендинг продукта «Гуляш» (Goulash.tech) для двух аудиторий и показать управляемую работу с ИИ.

Что просит заказчик (оригинал в `docs/brief.md`):
1. Выбрать аудитории и обосновать гипотезы.
2. Сделать посадочную страницу под аудитории: предложение, тексты, визуальная подача, при этом сайт остаётся узнаваемым «Гуляшом».
3. Добавить рабочий функционал: форма заявки (валидация, загрузка, результат) и интерактивные примеры интерфейса (кнопки, фильтры и переключатели реально работают на выдуманных данных).
4. Плюсом: ИИ для кода, логики, текстов, картинок и видео.

Результат сдачи: одна публичная ссылка, которая открывается с компьютера и телефона.

## 3. Технические ограничения

- Статический сайт: HTML, CSS, JavaScript. Без фреймворков, без сборки, без npm-зависимостей. Публикуется на GitHub Pages автоматически из папки `site/` при сохранении в ветку `main` (`.github/workflows/pages.yml`); должен работать и после перетаскивания папки `site/` на Netlify Drop.
- Только классические скрипты (`<script src=...>`), без ES-модулей, чтобы страница открывалась и через `file://`.
- Никаких внешних ресурсов во время работы: шрифты, иконки и скрипты лежат внутри `site/assets/`. Внешние только обычные ссылки `<a href>`.
- Логика вынесена в чистые функции, чтобы её можно было проверять тестами `node --test` (раздел 10). Файлы логики пишутся в формате UMD: внизу `if (typeof module !== 'undefined') module.exports = {...}`, а в браузере функции доступны через `window.GL`.
- Ссылки на CSS и JS с версией `?v=...`; при каждой выкладке значение меняется, чтобы телефон не держал старый кэш.
- Язык интерфейса и текстов: русский, `lang="ru"`.
- Вес сайта целиком не больше 5 МБ.
- Поддержка: последние Chrome, Safari и Firefox; ширины экрана от 360 до 1440 px.
- Не собирать и не хранить реальные персональные данные: форма работает на имитации отправки.

Структура файлов:

```
  index.html                 вход в корне, переводит на kitchens/

```

## 6. Форма заявки

Одна форма на странице для обеих ролей. Поля (атрибут `name`):

| name | Подпись | Обязательное | Правило |
|---|---|---|---|
| `name` | Как к вам обращаться | да | не меньше 2 символов после обрезки пробелов |
| `phone` | Телефон | да | маска `+7 (999) 123-45-67`; после очистки от нецифр и ведущей 7 или 8 ровно 10 цифр |
| `email` | Почта | нет | если заполнена, формат `x@y.z` |
| `city` | Город | да | не меньше 2 символов |
| `points` | Сколько у вас точек | да | целое число от 1 до 999 |
| `consent_pd` | Согласие на обработку персональных данных | да | чекбокс, по умолчанию выключен |
| `consent_ads` | Согласие на получение сообщений о продукте | нет | чекбокс, по умолчанию выключен |

Поведение:
- Валидация при потере фокуса и при отправке. Ошибка показывается текстом под полем, поле получает `aria-invalid="true"` и связь через `aria-describedby`.
- При попытке отправки с ошибками фокус уходит на первое невалидное поле, запрос не отправляется.
- При отправке: кнопка блокируется, на ней индикатор загрузки и текст «Отправляем…», поля блокируются. Длительность имитации по умолчанию 1200 мс.
- Успех: форма заменяется блоком «Заявка отправлена» с кратким текстом и кнопкой «Отправить ещё одну». Блок имеет `role="status"` и `aria-live="polite"`.
- Ошибка: над кнопкой блок «Не получилось отправить. Данные сохранены, попробуйте ещё раз» с кнопкой «Повторить»; введённые данные не теряются; `role="alert"`.
- Как вызвать ошибку для проверки: адрес с параметром `?simulate=error` (видимой ссылки на странице нет, решение Аси 2026-11-16).
- Пояснения «демо» под формой нет: о тестовом задании говорит только сноска в футере (решение Аси 2026-11-16). Форма по-прежнему только имитирует отправку.
- Ссылка на политику обработки данных ведёт на `https://goulash.tech/` (точный адрес документа уточняется, см. `docs/questions.md`).

Контракт функций (файл `lead-form-logic.js`, проверяется тестами):
- `formatPhone(raw)` возвращает строку в маске, работает при вводе по одному символу, обрезает лишнее.
- `validateLead(values)` возвращает `{ valid: boolean, errors: { [field]: string } }`. Сообщения на русском, короткие.
- `submitLead(values, opts)`: `opts = { simulate: 'ok' | 'error', delayMs: number }`. Возвращает `Promise`, который выполняется с `{ ok: true, id }` или `{ ok: false, error }`. Невалидные данные дают `{ ok: false, error: 'validation' }` без задержки.

## 7. Интерактивные демо (данные выдуманные, раскрыты в сноске футера)

Какие демо где:
- Блок «Демо» роли A (`#demo`): D1 доска заказов, D2 стоп-лист, D3 маршрут и ETA, по одному во вкладках.
- Блок «Своя доставка» роли B (`#own`): D5 калькулятор комиссий, D4 приложение гостя, во вкладках.

У каждого демо кнопка «Сбросить демо». Отдельных подписей «Демо-данные» у демо нет: вымышленность данных раскрывает сноска в футере (решение Аси 2026-11-16). Оговорка калькулятора D5 остаётся, это защита от «обещания результата», а не пометка демо.

Общие функции логики лежат в `demo-logic.js` и проверяются тестами.

### D1. Доска заказов (роль A)
- Четыре колонки: Новые, Готовятся, Готовы, В пути. В каждой счётчик.
- Начальные данные: 8 заказов трёх вымышленных брендов (названия нейтральные, не совпадающие с реальными), 3 курьера с разным расстоянием до кухни.
- Фильтр по бренду: чипы «Все» и по одному на бренд. Фильтр скрывает карточки и пересчитывает счётчики.
- Кнопки на карточке: в «Новых» «Принять» (карточка уходит в «Готовятся»), в «Готовятся» «Готово» (уходит в «Готовы»), в «Готовы» «Назначить курьера».
- «Назначить курьера» выбирает свободного курьера с минимальным расстоянием до кухни, карточка уходит в «В пути» и показывает имя курьера и ETA. Если свободных нет, показывается сообщение «Нет свободных курьеров», карточка остаётся.
- Кнопки «Новый заказ» нет (решение Аси 2026-11-16). Функция addRandomOrder в логике остаётся, на странице не используется.
- Функции: `advanceOrder(state, id)`, `assignCourier(state, id)`, `boardCounts(state, brand)`, `filterOrders(state, brand)`.

### D2. Стоп-лист (роль A)
- Список из 6 позиций с переключателем «в стопе» для каждой, сгруппировано по брендам.
- Рядом превью меню гостя: позиция в стопе серая с надписью «Нет в наличии» и неактивной кнопкой.
- Функции: `toggleStop(menu, itemId)`, `guestMenu(menu, brand)`.

### D3. Маршрут и ETA (роль A)
- SVG-карта: точка кухни, точка гостя, линия между ними.
- Переключатель способа доставки: пеший, вело, авто. Ползунок расстояния 1–10 км.
- ETA пересчитывается сразу, линия маршрута меняет стиль для каждого способа.
- Формула: `ETA = подготовка 12 мин + расстояние / скорость * 60`, скорости 5, 15, 30 км/ч, округление до целых минут.
- Функция: `etaMinutes(distanceKm, mode, prepMin = 12)`.

### D4. Приложение гостя (роль B)
- Рамка телефона, меню из 6 позиций с кнопками «+» и «−», корзина с итогом.
- «Оформить» запускает ускоренную имитацию статусов: Принят, Готовится, Курьер в пути, Доставлен (по 2 секунды). Прогресс виден как шаги: выполненные с галочкой, текущий с вращающимся кольцом, будущие пустые. После «Оформить» меню и корзина скрываются, остаётся строка «Ваш заказ на N ₽» и статусы.
- После «Доставлен» показывается начисление бонусов в демо-размере 5% от суммы, без подписи «демо»: вымышленность раскрывает сноска в футере (решение Аси 2026-11-17).
- Пустая корзина: кнопка «Оформить» неактивна. «Сбросить демо» останавливает таймеры и возвращает меню.

### D5. Калькулятор комиссий агрегаторов (роль B)
- Поля-ползунки: заказов в месяц (300–5000), средний чек (400–2500 ₽), доля заказов через агрегаторы (0–100%), комиссия агрегатора (10–40%), доля, которую удаётся перевести в свой канал (0–100%).
- Результат: комиссии сейчас, комиссии после перевода, разница в месяц.
- Обязательная подпись: «Иллюстрация по вашим допущениям. Не учитывает стоимость собственного канала и не является обещанием результата».
- Функция: `commissionSavings({ ordersPerMonth, avgCheck, aggregatorSharePct, commissionPct, shiftPct })` возвращает `{ currentCommission, afterCommission, savings }`.
  - `currentCommission = orders * avgCheck * share/100 * commission/100`
  - `afterCommission = orders * avgCheck * share/100 * (1 - shift/100) * commission/100`
  - `savings = currentCommission - afterCommission`

Требования ко всем демо: управление с клавиатуры (вкладки: стрелки, Home, End), видимый фокус, подписи у переключателей, изменения числа объявляются через `aria-live="polite"` там, где это уместно.

## 9. Доступность и качество

- Контраст текста не ниже 4.5:1 (проверяет ревьюер по токенам из `brand.md`).
- Все поля с `label`, все кнопки с понятным текстом, видимый `:focus-visible`.
- Заголовки по порядку: один `h1`, дальше `h2`; внутри блока «Своя доставка» `h3` и `h4`.
- На экране 360 px нет горизонтальной прокрутки.
- Нет ошибок в консоли браузера при загрузке и работе демо.
- При `prefers-reduced-motion` анимации останавливаются или заменяются статичным кадром.

## 11. Процесс и контрольные точки

Порядок: правки по `docs/tickets.md` → `/verify` → `/ship` → `/retro`.

Контрольные точки человека:
- C1. Ася утверждает ТЗ и тексты до запуска разработки (отмечена для версии 1.0; версию 2.0 переписал агент по просьбе Аси, Ася подтвердила 2026-11-17).
- C2. Ася смотрит страницу целиком (обе роли) и пишет правки в `docs/feedback.md`. Лендинга B больше нет, поэтому C2 теперь означает приёмку объединённой страницы.
- C3. Финал. Агенты считают, что всё готово, создают `docs/handoff.md` со статусом по каждому AC и списком того, что нужно проверить глазами. Ася вносит правки.

Definition of Done для тикета: код написан, `node scripts/check.mjs` и `node --test` без ошибок, ревьюер не нашёл блокирующих замечаний, статус тикета обновлён.

Ограничения автоматики: максимум 2 круга «ревью → правка» на тикет. Если после двух кругов есть блокер, тикет получает статус `blocked`, причина записывается в `docs/questions.md`, работа идёт дальше к независимым тикетам.

## 12. Вне объёма

Отдельный лендинг B и страница выбора, реальная отправка заявок, серверная часть, аналитика, CMS, многоязычность, SEO-оптимизация сверх базовых тегов, копирование чужих текстов и графики с goulash.tech.

## 13. Допущения и открытые вопросы

- Допущение: «виртуальные бренды» в Гуляше заводятся как отдельные заведения в одном кабинете. Это гипотеза для теста, в текстах формулировки осторожные.
- Допущение (2026-11-17): страница остаётся по адресу `kitchens/`, а корень сайта переводит на неё. Перенос страницы в корень возможен, но меняет все пути к ресурсам; делать только по решению Аси.
- Вопрос: точный адрес политики обработки персональных данных.
- Вопрос: `<title>` и `description` страницы говорят только о гост-китченах. Допущение: оставляем, роль A основная; при желании Ася дописывает общий вариант в copy-файл.
